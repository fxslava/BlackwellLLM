READY FOR A/B DIFFING
---------------------
Run a later checkpoint (Lattice-OBS, Split-K, Hadamard, MMA-permuted pack, ...) with
the SAME four flags that matter - --limit 50 --max-input-tokens 2000 --ctx 4096 and
the same --kv-mode/--prefill - into a NEW output directory, then:

    python benchmarks/report_tables.py benchmarks/results/<new-run> \
           --against benchmarks/results/e8w5_baseline

That pairs samples by (task, _id), reports per-sample deltas, the win/loss/tie split,
a paired t-statistic, and the largest individual regressions with both predictions
side by side. Use the paired t, not the task averages: the +/- above is 4.5-5.5 points,
so an unpaired comparison cannot see a real change smaller than ~10 points, while the
paired test on identical samples resolves far less.

DO NOT re-run into this directory. The harness OPENS predictions.jsonl IN APPEND MODE
("a"), so a second run here silently appends 200 more rows and report_tables.py would
then read whichever row for a given (task, _id) it saw last. Use a new --output-dir.
(--resume exists for continuing an INTERRUPTED run; this one is complete.)

The three artifacts are marked read-only to enforce that. To deliberately modify them:
    attrib -R benchmarks\results\e8w5_baseline\*

WHAT WOULD MAKE THIS BASELINE BETTER (in value order)
-----------------------------------------------------
1. Re-run at --max-input-tokens 16000: truncates only 3/200 samples, ~7.0 h. That
   number is citable against published LongBench; this one is only self-comparable.
2. Finish the decode diagnosis (the cancelled 2-minute A/B). Decode is the repo's
   actual hot path - short prompt, long generation - and it is 4.6x prefill per token.
3. A paired BF16 subset. GLM-4-9B-Chat-1M-hf is 18 GB against 12 GB of VRAM, so it
   needs --gpu-layers 17 and streams 23 of 40 layers per token; a full run is a
   multi-day job, but ~20 samples at a 500-token budget is roughly an hour and would
   replace the 83-token perplexity A/B with a real quality delta.
